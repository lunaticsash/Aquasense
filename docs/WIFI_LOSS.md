# Testing Wi-Fi loss mid-operation

I would test two cases separately: the phone losing Wi-Fi, and the device losing Wi-Fi. For the phone, I would send a pump command and then switch on airplane mode or throttle the network (Chrome DevTools, Network Link Conditioner) at three moments: before the request leaves, while it is in flight, and after the server has processed it but before the reply comes back. In all three, the app should show "offline, last updated X min ago" instead of an old value passed off as live, and it should retry with backoff. The third moment is the risky one. After reconnecting, the app should fetch the real pump_state rather than assume the command failed, and a retry must not switch the pump twice (idempotency key or a state check before resending). For the device case, I would turn off the router or block the device in it, then check that last_seen goes stale, the app marks the device offline after the threshold (5 minutes, my assumption), and the control buttons are disabled or show a clear message. Then I would bring Wi-Fi back and confirm the app recovers without a restart, and I would also flip the connection on and off every few seconds to look for UI flicker or piled-up requests.
